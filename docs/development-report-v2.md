# 产品风险评估系统产品定义书

> 本文档阐述系统的产品定位、核心能力边界、数据架构与功能设计。
> 不限定具体技术实现方案，以确保系统的长期可扩展性和能力上限不受制于选型。

---

## 一、产品背景与定位

### 1.1 问题空间

在进出口监管场景中，风险评估面临三个根本性挑战：

**信息分散** — 相关风险信号散布于数百个不同语种、不同格式、不同机构的公开信息源中，人工检索效率极低，且无法做到实时覆盖。

**异构性** — 同一制造商的同一种风险行为，可能同时出现在欧盟的召回数据库、美国消费品安全委员会的公告、世界卫生组织的食安预警、以及国内口岸的查验记录中。这些信息彼此孤立，没有被关联。

**滞后性** — 从境外监管机构发布公告，到国内监管部门获取信息、形成判断、落地执行，往往存在数天到数周的时差。走私分子正是利用这个时间窗口。

### 1.2 产品愿景

**一句话定位：构建海关进出口领域的全品类智能风险感知平台，以主动预判替代被动响应。**

三个层次的目标：

1. **看得更全** — 将海关进出口商品相关的各类风险信号（产品安全、质量合规、贸易管制、外汇合规、生物安全等）纳入统一感知体系；
2. **看得更深** — 从单一事件识别升级为关联图谱推理，从已发生风险预警升级为风险趋势预判；
3. **看得更准** — 通过多语言语义理解和文档智能解析，将非结构化信息转化为结构化情报，将噪音降到最低。

## 二、品类与风险域定义

### 2.1 覆盖品类

本系统不限定于单一商品类别，而是将进出口风险划分为若干**风险域**，每个域有独立的信号采集通道、评分维度和预警规则：

| 风险域 | 核心关注点 | 代表性风险信号 |
|--------|-----------|--------------|
| **产品安全** | 进口机电、食品、化妆品等消费品的质量与安全事故 | 境外召回通告、监管机构警示、不合格产品通报 |
| **贸易合规** | 进出口许可、产地来源、知识产权、海关估价 | 许可证过期、原产地证书异常、价格瞒骗信号 |
| **生物安全** | 外来入侵物种、动植物疫病、食品安全 | 入境截获有害生物、进口食品检出禁用药剂 |
| **危化安全** | 危险货物包装、UN 分类合规、MSDS 准确性 | 危货误报、MSDS 与实际货物不符、包装标识错误 |
| **金融合规** | 跨境资金流与物流一致性、转移定价 | 高报低出、资金流与货物流分离、异常结算周期 |
| **碳与环境合规** | 碳足迹核查、绿色贸易壁垒、进口废物 | 碳标签缺失、出口国认证不被认可、废物伪装进口 |

> **设计原则**：系统核心框架与具体品类无关。新增一个风险域时，只需注册新的信号源配置、评分维度和预警规则，无需修改核心引擎。

### 2.2 核心数据实体

系统的所有功能围绕以下核心实体展开：

**风险事件（Risk Event）** — 从外部信号源采集并结构化后的最小风险记录单位：

```
风险事件 = {
    事件标识符（全局唯一ID）
    原始来源（哪个数据源首次报告）
    发布时间（境外原始发布时间）
    采集时间（进入本系统的时间）
    申报批次（关联的进出口申报单号）
    国别（事件发生/发布所在国家）
    制造商（境外生产企业名称）
    产品名称（牌号/型号/规格）
    产品类别（HS 编码 + 品类名称）
    危害类型（物理伤害/化学危害/电气安全/生物污染等）
    严重程度（国际标准等级：严重/一般/轻微）
    原始文本描述（原始公告的完整正文）
    原文语言（用于判断是否需要多语言处理）
    结构化提取字段（产品名、型号、批次等）
    关联企业（通过企业图谱关联的境内企业）
    风险评分（当前综合风险分）
    风险等级（最终判定：S/M/L/A）
    状态（待处理/已复核/已归档）
}
```

**企业实体（Enterprise Entity）** — 系统中的企业不只是一个名字，而是一个具有多维属性的节点：

```
企业实体 = {
    企业标识符
    企业名称（境内/境外）
    统一社会信用代码 /境外企业注册号
    企业类型（生产企业/贸易商/报关行/货运代理）
    所属国家
    股权关联企业列表（关联图谱）
    商业关联企业列表（同一发货人/收货人链路）
    物流关联记录（同一航次/舱位记录）
    海关信用等级
    累计违规次数
    最近一次违规时间
    综合风险画像向量（各维度风险分）
    标签（疑似转移定价/疑似固体废物等）
}
```

## 三、外部信号源体系

### 3.1 信号源的分类

系统接入的外部信号源按**信息类型**分为四类：

| 类型 | 描述 | 示例 |
|------|------|------|
| **A类 — 官方监管数据库** | 各國监管机构公开发布的结构化或半结构化数据库，可定期轮询 | 欧盟 Safety Gate、美国 CPSC 召回、英国 OPSS 公告、中国 GACC 警示 |
| **B类 — 官方公报与文件** | 监管机构官网发布的非结构化公告，需要语义理解提取关键信息 | 各国食药监公告、质检总局通报、WTO/TBT 通报 |
| **C类 — 新闻与情报来源** | 专业新闻媒体的合规相关报道、行业分析报告 | 华尔街日报贸易专栏、路透社海关新闻、专业行业媒体 |
| **D类 — 内部业务数据** | 海关内部积累的历史查验记录、化验结果、缉私案件 | 查验结果数据库、化验鉴定记录、案件卷宗 |

**A 类数据源**（当前已接入）：

| 编号 | 名称 | URL | 类型 | 频率 |
|------|------|-----|------|------|
| S-01 | 美国 CPSC 消费品召回 | cpsc.gov/Recalls | A类-Web | 每6小时 |
| S-02 | 欧盟 Safety Gate 警示 | ec.europa.eu/safety-gate | A类-Web | 每6小时 |
| S-03 | 英国 OPSS 产品安全 | gov.uk/product-recalls-and-alerts | A类-Web | 每日 |
| S-04 | 澳大利亚产品安全 | productsafety.gov.au | A类-Web | 每日 |

**B/C/D 类数据源**（待扩展方向）：

| 类型 | 代表性来源 | 扩展难度 | 价值 |
|------|-----------|---------|------|
| B-食安 | WHO/FAO 食品安安全网络、EFSA 科学意见 | 中（PDF 格式为主） | 高 |
| B-机电 | IECEE 公告、UNECE WP.29 法规更新 | 低（结构化网页） | 高 |
| B-危化 | UN TDG 分类更新、IMO 危货通知 | 低 | 高 |
| C-金融 | BIS 实体清单更新、OFAC 制裁名单 | 低（机器可读） | 高 |
| D-内部 | 各直属海关查验结果库、化验中心鉴定记录 | 高（需跨系统对接） | 极高 |
| D-企业 | 国家企业信用信息公示系统 | 中（需授权接口） | 极高 |

### 3.2 多语言风险信号挖掘（AI 扩展方向一）

**问题**：当前系统的 A 类数据源以英语为主，但产品安全的真实风险信号往往以小语种发布（如日本的 JIS 通报、巴西的 INMETRO 公告、韩国的 KATS 警示），或出现在地方性监管机构的小众页面中。依赖人工翻译会导致关键风险信号被遗漏。

**设计目标**：建立多语言信号挖掘管道，将散布于各语种中的风险信息统一归一化。

**工作方式**：

1. **语种自动识别** — 对原始页面内容进行语种检测（置信度阈值可配置），自动判断是否属于系统当前处理语言范围；
2. **关键信息抽取** — 对非系统主语言的页面，调用多语言语义模型提取风险相关字段（产品名称、制造商、风险类型、采取措施），以结构化格式输出；
3. **跨语言消重** — 当同一制造商的同一风险事件同时出现在英语页面和小语种页面时，自动识别为同一事件，避免重复录入；
4. **语义升级检测** — 追踪同一条风险公告的语义变化：从"建议关注"到"紧急撤回"，从"自愿召回"到"强制措施"，自动识别风险升级信号并重新触发评分。

**输入**：任意语言的风险公告原始文本（或网页截图作为多模态备选）。
**输出**：标准化的风险事件字段 + 原始语言标注 + 语义强度标签（正常/升级/恶化）。

### 3.3 文档智能解析（AI 扩展方向二）

**问题**：海关日常业务中存在大量需要人工审阅的随附单据——商业发票、装箱单、原产地证书、检验报告、MSDS 等。这些文档承载着申报信息与实际货物之间的比对依据，但全靠人工核验效率低且容易疲劳出错。

**设计目标**：构建单据智能解析引擎，自动从各类单据中提取申报要素，与报关单信息进行智能比对，识别异常并给出核查建议。

**三类核心解析能力**：

**① 商业发票智能解析**

从发票 PDF 或扫描件中提取：
- 买方/卖方信息（名称、地址、国别）
- 商品描述（品名、规格、型号）
- 成交数量与单价
- 成交方式（FOB/CIF/CFR）
- 币种与总价
- 船名/航次/箱号

与同批次报关单进行自动化要素比对，识别：
- 申报价格与发票价格差异（超出容差阈值）
- 申报品名与发票品名不一致
- HS 编码归类差异（基于商品描述自动推荐编码）
- 成交方式与统计金额不匹配

**② 原产地证书解析与核验**

从原产地证书中提取：
- 签证机构名称与编号
- 出口商/生产商信息
- 原产国
- 商品描述与 HS 编码
- 签证日期与有效期

自动核实：
- 签证机构与原产国官方授权机构是否匹配
- 证书格式与该国官方证书格式的一致性（识别伪造证书的格式特征）
- 与已知真实证书样本的视觉特征比对（纸张、印章、签名位置）

**③ 检验报告与 MSDS 解析**

从检验报告/质量证书中提取检测项目、检测方法、检测结果、结论。
从 MSDS（化学品安全技术说明书）中提取产品成分、危险等级、安全措施、应急处置。

与货物实际申报信息交叉核验：
- 检验项目与申报品名是否匹配（检测了不存在的成分）
- MSDS 中的危险等级与危货申报是否一致
- 检验结论与货物属性是否矛盾

**输入**：PDF 文件、图片（支持扫描件）。
**输出**：结构化提取字段 + 与报关单的要素比对结果 + 异常标记与风险分。

## 四、风险评估引擎

### 4.1 多维评分体系

系统采用**六维风险评分框架**，每个维度独立计算子分，最终加权汇总为综合风险分：

```
综合风险分 = f(严重度分, 概率分, 国别分, 品类分, 时效分, 因果传导分)

风险等级映射：
  S（极高）：综合分 ≥ 85
  M（高）  ：综合分 70-84
  L（中）  ：综合分 50-69
  A（低）  ：综合分 < 50
```

**各维度含义**：

| 维度 | 衡量什么 | 数据来源 |
|------|---------|---------|
| 严重度分 | 该类危害在国际标准中的公认严重程度 | 危害类型定义表 + 国际标准映射 |
| 概率分 | 同类事件在历史中出现频率与近期趋势 | 事件库统计 + 时序模型 |
| 国别分 | 来源国/制造商所在国的整体合规水平 | 国别合规画像（基于历史事件统计） |
| 品类分 | 该产品类别（HS 编码层级）的整体风险特征 | 品类画像（基于历史查验结果） |
| 时效分 | 该事件是近期新发还是历史累积 | 发布时间 vs 当前时间 + 衰减曲线 |
| 因果传导分 | 该制造商/供应商的历史行为模式（因果图谱节点评分） | 因果知识图谱 |

### 4.2 评分刷新机制

**现状局限**：事件在入库时一次性评分，后续除非人工修改否则不变。

**扩展方向（架构上预留）**：引入**动态评分刷新**机制：

- 当同一实体（企业/产品类别/国别）出现新信号时，自动触发相关联的所有历史事件重新计算综合分；
- 新信号按贝叶斯方法更新风险概率估计，而非一次性替换；
- 时效维度引入自然衰减：超过一定年限的事件在无新信号情况下其分数自动向均值回归。

### 4.3 关联评分增强（AI 扩展方向三）

单一事件的评分是基础，但真正的走私违规往往是**多个低风险信号的同时出现**。例如：

- 某企业申报的 HS 编码与实际产品描述存在轻微不符（单看风险低）
- 该企业的境外发货人在其他口岸近期被查验发现质量问题（单看是外部信息）
- 该企业首次在系统出现（新鲜实体，风险未知）

三个独立信号分别风险都低，但组合后综合判断：**这是一起疑似伪瞒报商品性质 + 转移定价的复合违规，建议触发高风险预警。**

这种关联判断依赖**企业关联知识图谱**，见下一节。

## 五、企业关联知识图谱

### 5.1 图谱结构

企业关联知识图谱以**节点**和**边**为核心结构：

**节点类型**：

```
企业节点：
  - 境内收发货人
  - 境外发货人
  - 申报单位（报关行）
  - 货运代理
  - 承运人（船公司/航空公司）
  - 境外工厂/品牌方
  - 最终买家

产品节点：
  - 产品类别（HS 层级）
  - 具体产品型号
  - 原材料/零部件

事件节点：
  - 风险事件（来自外部数据源）
  - 查验记录（来自内部数据）
  - 预警记录
```

**边类型**：

| 边类型 | 含义 | 权重依据 |
|--------|------|---------|
| 股权关联 | 两企业存在交叉持股关系 | 工商登记数据 |
| 人员关联 | 同一法人代表/高管团队 | 工商登记数据 |
| 物流关联 | 使用同一航次/同一舱位 | 舱单数据 |
| 商业关联 | 同一境外发货人对应多家境内收货人 | 报关数据统计 |
| 申报关联 | 同一申报单位代理的多家企业 | 报关行作业数据 |
| 事件关联 | 涉及同一产品的不同风险事件 | 事件库自然关联 |
| 地理关联 | 注册地/装货港相同 | 地址数据 |

### 5.2 图谱推理能力

**① 风险传导推理**

当某个节点触发预警时，自动展开其关联路径并计算综合风险暴露：

```
某境外工厂节点 F 触发高风险预警
  → 展开所有使用 F 货物的境内收货人企业节点 E1, E2, E3
  → 展开 E1, E2, E3 申报的所有同批次货物
  → 自动评估：F 的风险通过供应链传导到哪些具体货物和申报单
  → 输出：受影响企业清单 + 受影响货物清单 + 建议布控范围
```

**② 异常关联模式识别**

系统持续监控图谱中的异常拓扑结构，自动识别以下高风险模式：

- **"影子工厂"模式**：多家境内收货人企业均由同一神秘境外发货人供货，且这些境内收货人相互之间无股权关系但实际控制人相同
- **"洗货通道"模式**：某报关行代理的货物频繁出现归类差错，且归类方向一致指向低税率品类
- **"空壳链"模式**：新设企业在短暂活跃后消失，其股权关联的新设企业接替其业务

**③ 企业合规画像**

基于图谱中的多维行为数据，为每个企业节点生成**综合合规画像**，包含：

- **基础信用层**：海关信用等级、注册年限、企业规模
- **合规历史层**：违规频次、违规类型分布、违规时间加速度（趋势）
- **图谱关联层**：上下游企业中是否存在高风险实体、是否处于已知异常模式中
- **实时信号层**：最近是否有新发生的外部风险事件与该企业相关联

画像结果用于：
- 企业注册时的预审（新的收货人注册时，自动查询图谱判断是否有关联高风险企业）
- 查验决策：结合企业画像和货物风险，给出个性化查验建议
- 分级管理：A/B/C/D 四级企业分类，对应不同通关便利和查验比例

### 5.3 因果知识图谱与风险传导

在企业关联知识图谱之下，还存在一个细粒度的**因果知识图谱**，专门建模产品层面的风险传导链条：

```
供应商 S → 原材料/零部件类型 C → 制造缺陷类别 D → 危害类型 H → 事故严重度 S

每条边携带：
  - 传导系数（风险在该环节的放大或衰减倍数）
  - 统计置信度（基于多少历史事件得出的统计关系）
  - 因果方向（正向传导 / 反馈抑制）
```

因果图谱的应用价值：
- **正向推导**：当某原材料出现风险时，估算其下游所有相关产品的风险增量
- **反事实推理**：如果更换某个供应商，风险会降低多少？
- **反馈学习**：当人工复核持续降低某制造商的评分时，该信号会传递到因果图谱的对应节点，自动调整其传导系数

## 六、预警与规则体系

### 6.1 预警规则引擎

预警规则是一组**条件-动作**结构：

```
规则 = {
    规则名称
    条件（可嵌套的布尔表达式，支持阈值/时间窗口/趋势判断）
    触发后的动作（推送预警/记录日志/触发 Agent）
    规则状态（启用/禁用）
    优先级（S/M/L 三级）
    适用风险域（可选限定）
}
```

**条件表达式的典型类型**：

| 条件类型 | 示例 |
|---------|------|
| 阈值条件 | 某企业 30 天内违规次数 ≥ 3 |
| 趋势条件 | 某品类风险分连续 3 周上升 |
| 关联条件 | 同批次货物 + 关联图谱中有高风险企业 |
| 组合条件 | 国别分 > 80 AND 品类分 > 70 AND 时效分 < 30 天 |
| 外部信号条件 | 某制造商被境外监管机构新发布召回公告 |

### 6.2 自然语言规则配置（AI 增强方向）

**问题**：业务专家脑中有一套预警逻辑，但将这套逻辑转译为 YAML 配置需要 IT 人员协助，效率低且容易信息损失。

**设计目标**：允许业务人员用自然语言描述预警需求，系统自动解析为结构化规则配置。

**示例**：

业务人员输入：
> "如果来自欧盟的食品类货物，在过去30天内被我们的系统累计记录了5次以上的违规事件，并且其中至少2次涉及农药残留问题，就给我发一个橙色预警。"

系统自动解析：
```
{
  "condition": {
    "type": "AND",
    "sub_conditions": [
      {"type": "field_match", "field": "country_group", "operator": "in", "value": ["EU"]},
      {"type": "risk_domain", "value": "food_safety"},
      {"type": "time_window", "window": "30d", "aggregator": "count",
       "filter": {"hazard_type": "pesticide_residue"}, "threshold": 2},
      {"type": "time_window", "window": "30d", "aggregator": "count", "threshold": 5}
    ]
  },
  "severity": "warning",
  "action": ["dashboard", "notification"]
}
```

解析过程调用多语言语义理解模型，具备：
- 否定理解（"不涉及农药残留"与"涉及农药残留"需正确区分）
- 时间表达解析（"过去30天"、"最近一周"、"自...以来"）
- 聚合函数理解（"累计"、"至少有"、"超过"）
- 上下文纠偏（同义表述如"农药残留"="农残"="农药超标"统一归一）

### 6.3 预警分级响应

预警按严重程度分为三级：

| 级别 | 触发条件示例 | 系统动作 |
|------|------------|---------|
| 🔴 红色预警 | 极高风险事件 + 高风险关联企业 + 趋势上升 | 立即推送 + 自动建议布控 + Agent 启动调查 |
| 🟠 橙色预警 | 多维评分同时偏高 + 关联图谱异常 | 推送 + 进入复核队列 |
| 🟡 黄色预警 | 单维度异常 | 记录 + 纳入统计 + 趋势观察 |

## 七、闭环反馈机制

### 7.1 人工复核的价值

人工复核不只是一个"确认"操作，而是系统最重要的**学习信号来源**：

- 每一次人工修正（原始评分 → 实际评分）都是一次有标签的数据样本
- 修正的方向（向上调高 / 向下调低）和幅度（从 A→M 与从 S→L 的幅度差异）都携带信息
- 修正原因的自由文本记录，经过语义分析后可发现系统未捕捉到的新风险维度

### 7.2 反馈学习引擎

反馈学习引擎接收复核记录，输出两类结果：

**① 模型系数调整建议**

对每个评分维度（国别、品类、严重度等），计算：
- 该维度的历史修正一致性（是否同类事件被系统性地高估或低估）
- 修正幅度的统计显著性（排除随机噪声）
- 调整建议值（保守幅度，防止单次调整造成模型震荡）

满足触发阈值（一致性 ≥ 70%，样本数 ≥ 5 条，幅度 ≥ 5%）的调整，经人工确认后写入模型配置。

**② 因果图谱节点更新**

当某制造商节点连续被降级修正（且一致性达标）时：
- 自动更新该制造商节点的因果风险评分
- 将反馈信号沿因果链向上下游传导
- 生成学习日志供人工审计

### 7.3 预警效果评估

系统定期（可配置为周/双周/月）自动评估预警有效性：

- 本周期触发的预警，最终有多少被人工确认为"有效预警"？
- 有多少实际发生的风险事件，系统**未能**提前预警（漏警分析）？
- 哪些规则的误报率持续偏高，需要调整条件？

评估结果以可视化报表呈现，供规则维护人员优化参考。

## 八、产品安全与合规体系

### 8.1 操作审计

系统对以下操作完整记录审计日志：

- 任何配置对象的创建、修改、发布、回滚
- 预警规则的启用/禁用/修改
- 模型参数的调整（任何手动干预）
- 流水线的手动触发与参数覆盖
- 用户登录与权限变更

审计日志不可删除、不覆盖，按时间顺序永久保留，支持按操作人/时间/对象类型多维查询。

### 8.2 数据安全

- 所有原始页面内容、解析中间结果一经采集永久存档，支持事后溯源举证
- 企业关联图谱数据中涉及商业敏感信息的部分，支持按需脱敏展示
- 用户权限分为：业务操作员（只读+复核）、规则管理员（可配置规则）、系统管理员（全部权限）

### 8.3 健康监控与通知

系统持续监控以下健康指标：

| 监控对象 | 指标 | 告警阈值 |
|---------|------|---------|
| 数据源 | 可用率、响应延迟、数据新鲜度 | 连续 3 次失败 / 延迟 > 30s |
| 流水线 | 各阶段成功率、运行时长 | 阶段失败 / 单阶段 > 2h |
| 预警规则 | 有效率、误报率（周环比） | 有效率 < 60% / 误报率 > 40% |
| 企业图谱 | 新增节点数、关联异常模式触发次数 | 异常模式出现 |

告警自动写入通知中心，支持按严重程度分级推送到相应人员的操作界面。

## 十、产品路线原则

本系统的扩展遵循以下原则，以确保长期方向不受短期实现约束：

**信号驱动而非功能驱动** — 优先扩展新的风险信号源接入能力，而非在已有信号上堆砌功能。新的数据源就是新的风险感知能力。

**图谱优先于报表** — 关系信息（企业关联、供应链、因果链）优先于统计信息（汇总数字、周同比）沉淀为可推理的知识，而非一次性的报表输出。

**自然语言作为入口** — 业务人员的专业知识应能直接转化为系统能力，而非必须经过 IT 转译。自然语言配置是最优先降低使用门槛的方向。

**闭环可测试** — 每个 AI/模型增强功能必须有可量化的效果评估指标。预警有效率、漏警率、人工复核采纳率等指标定期审视，不设无法验证的"智能"功能。

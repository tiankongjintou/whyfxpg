## 一、已知缺陷清单

### 1.1 高优先级缺陷

#### 缺陷1：风险等级阈值与需求书不一致

**描述**：需求书定义风险等级阈值为 S≥85, M≥70-84, L≥50-69, A<50，但代码中实现为 S≥8000, M≥3000, L≥1000, A<1000。

**位置**：`whyfxpg/core/risk_scorer.py` 的 `map_to_risk_level()` 方法

**复现步骤**：
```python
from whyfxpg.core.risk_scorer import RiskScorer
from whyfxpg.config.models import RiskModelConfig

# 创建一个总分 80 的事件
scorer = RiskScorer(RiskModelConfig())
result = scorer.map_to_risk_level(80)
print(result)  # 输出 'A'，但需求书定义 80 应该在 M 范围
```

**影响**：风险等级判定逻辑与产品定义书严重不符，可能导致误判。

**修复建议**：将阈值配置化为可调整参数，并按需求书重新设置默认值。

---

#### 缺陷2：多语言字段缺失

**描述**：`risk_events` 表缺少 `extracted_language` 字段，无法支持多语言风险信号挖掘。

**位置**：
- `whyfxpg/core/extract_engine.py` — 抽取时不填此字段
- 数据库 schema — 表中无此字段

**复现步骤**：
```python
import sqlite3
conn = sqlite3.connect('whyfxpg/data/whyfxpg.db')
cur = conn.cursor()
cur.execute("PRAGMA table_info(risk_events)")
columns = [r[1] for r in cur.fetchall()]
print('extracted_language' in columns)  # False
```

**影响**：多语言处理功能无法实现，无法区分风险信号的原文语言。

**修复建议**：
1. 添加数据库迁移脚本，增加 `extracted_language` 字段
2. 在 `extract_engine.py` 中调用语言检测模型填充此字段

#### 缺陷4：自然语言规则配置未实现

**描述**：需求书定义预警规则支持 `raw_text` 自然语言原始输入和 `condition_json` 结构化条件，但 AlertRule 模型中仅有一个 `condition: Dict` 字段。

**位置**：
- `whyfxpg/config/models.py` 的 `AlertRule` 类
- `whyfxpg/core/rule_engine.py` — 无自然语言解析逻辑

**复现步骤**：
```python
from whyfxpg.config.models import AlertRule

rule = AlertRule.from_dict({
    "rule_id": "test",
    "name": "测试规则",
    "raw_text": "如果来自欧盟的食品在过去30天有5次以上违规就发预警"
```

**影响**：业务人员无法以自然语言配置预警规则，必须通过结构化表单。

1. AlertRule 模型增加 `raw_text` 和 `condition_json` 字段

### 1.2 中优先级缺陷

#### 缺陷5：时效衰减未实现

**描述**：需求书定义的时效分维度（发布时间衰减曲线）未实现，所有事件按同一权重计算。

**位置**：`whyfxpg/core/risk_scorer.py` — 评分公式中无时效因子

**修复建议**：在 `RiskScorer.score()` 中增加时效分计算：
```python
def time_factor(self, publish_date) -> float:
    days_old = (datetime.now() - publish_date).days
    decay = math.exp(-days_old / half_life)
    return max(0.5, min(1.0, decay))
```

```python
# risk_events 表常用查询字段
```

## 四、重构建议

### 4.1 评分模块重构

当前 `RiskScorer` 使用乘法聚合各维度分数，可能导致数值溢出。建议引入加权求和或对数变换：

```python
# 当前（有问题）：
total = ss * ps * country * product * history * evidence * causal

# 建议（对数变换）：
import math
log_score = (math.log(ss+1) + math.log(ps+1) + 
              math.log(country+1) + math.log(product+1) +
              math.log(history+1) + math.log(evidence+1) +
              math.log(causal+1))
total = math.exp(log_score)  # 避免乘法溢出
```

### 4.2 规则引擎解耦

当前 `rule_engine.py` 混杂了编排逻辑和具体编译实现，建议拆分为：
- `RuleCompiler` — 纯编译逻辑
- `RuleEvaluator` — 纯求值逻辑
- `RuleEngine` — 仅做编排

### 4.3 存储层统一

`stores/` 目录下有多个 store 实现，建议统一抽象为 Repository 模式：
```python
class RiskEventRepository:
    def add(event)
    def get(event_id)
    def query(filters)
    def update(event_id, data)
```

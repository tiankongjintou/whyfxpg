# ADR-001: 选择重构而非重写

状态：accepted
日期：2026-07-28

## 背景

WHYFXPG 的架构审计（architecture-review-whyfxpg-2026-07-28.html）识别出多处浅模块与 seam 泄漏：LLM 全局单例、各模块自行管理数据库连接、预警写入重复、UI 与 SQL 混合等。

团队只有一个核心开发者，系统已具备完整业务链路与测试覆盖。

## 决定

采用**分阶段重构**，不进行全面重写。

## 理由

1. 重写会丢失已验证的评分模型、因果图、报告生成逻辑，并引入新 bug。当前系统**功能价值高于代码整洁度**。
2. 关键痛点是**事务/连接 locality** 与**外部依赖端口**，可通过 seam 适配器解决，无需推翻领域模型。
3. 单人维护节奏更适合“小步快跑、测试护航”的增量重构，而非一次性大规模重写。

## 影响

- 优先引入 `UnitOfWork`、`Store` 层、LLM/Fetcher 端口。
- 不改动数据库 schema，不删除现有模块；旧接口在过渡期内保留默认回退。
- 每完成一个阶段补充一条 ADR。

## 反对意见与回应

- “重写一次性能更干净。” 回应：干净代码不等于可运行系统；先让当前可运行系统变得可测试，再考虑替换局部实现。

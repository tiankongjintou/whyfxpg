## 二、新智能体注册流程

当启动新的智能体（无论是通过 delegate_task 还是新的 cron）时，必须：

1. 在本文件添加一行注册记录
2. 在 commit message 中标注智能体名称
3. 在每次 action 的输出开头标注身份：`[AgentName] 执行操作：XXX`

## 三、时间线管理规范

### 3.1 Commit 消息格式

所有 commit 必须包含智能体身份标识：

```
[AgentName] 动作：简短描述

详细说明（可选）

Agent: agent-name | Date: YYYY-MM-DD | Phase: PhaseX
```

**示例**：
```
[Phase0-Executor] fix: 修复风险等级阈值 S≥8000→S≥85

修复了 risk_scorer.py 中 map_to_risk_level() 的硬编码阈值问题。
验证：输入总分80，输出从'A'修正为'M'。

Agent: Phase0-Executor | Date: 2026-08-10 | Phase: Phase0
```

### 3.2 决策记录格式

当智能体做出重大决策时，必须在 `docs/adr/` 下新增 ADR 记录：

```
docs/adr/024-YYYY-MM-DD-short-description.md
```

ADR 格式：
```markdown
# ADR-024: 短标题

日期：YYYY-MM-DD
决策者：[AgentName]
问题：[描述问题]
决策：[描述决策]
理由：[为什么这样决策]
```

### 3.3 任务卡状态更新

所有任务卡状态变更必须附带：
- 智能体名称
- 时间戳
- 状态变更原因

## 六、重大决策上报规则

以下情况必须通过飞书消息通知用户，不得自行决定：

1. **需求变更**：发现需求书与代码不一致
2. **技术选型重大变更**：更换框架、数据库、API 设计
3. **工作量超出预期**：单任务预估超过 2 人天
4. **质量指标不达标**：测试覆盖率低于 50%
5. **发现 P0 安全漏洞**：数据泄露、权限绕过
6. **里程碑偏离**：Phase 内任务进度落后超过 30%

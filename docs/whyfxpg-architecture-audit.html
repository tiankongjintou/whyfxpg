🔬 Deep / Shallow 模块评分

判断标准：接口越窄（公开成员少）、实现越厚（业务复杂）、被越多外部调用 → 越深；反之越浅。

🔥 热点与局部性违规

  • 最大热点：core/stores.py 746 LOC，包含 UnitOfWork、AlertStore、RiskEventStore、SummaryStore、CausalGraphStore 等。违反“一个文件一个概念”的 locality。
  • 认知复杂度冠军：webui/bigscreen.render_bigscreen 认知复杂度 18；core/risk_model.run 19；core/causal_knowledge.explain_event 21。说明这些函数仍承担多段不相关决策。
  • UI 层泄漏：webui/screens/causal.py 直接调用 init_db()、init_causal_schema() 与 CausalKnowledge，是 screens 中唯一导入 core.db 的模块。
  • legacy 依赖：adapters/llm/openai_compat_adapter.py 仍回退到 core.llm_client，意味着旧的全局单例仍是实际 HTTP 实现。
  • 低利用率：core/feedback_learner.py 410 LOC 仅被 1 个文件导入，可能是“规划了但未使用”的功能。

📈 推荐路线图

R1 · 拆分 core/stores.py（最高 leverage）
将 UnitOfWork、AlertStore、RiskEventStore、SummaryStore、CausalGraphStore 拆为独立模块。 每个 store 的接口宽度会从 82 降到 ~6–10，locality 显著提升。
R2 · 消除 UI 最后一个 core.db 泄漏
将 webui/screens/causal.py 改为调用 CausalPort（注入 DbCausalAdapter）或新的 CausalService，不再直接 import core.db 与 CausalKnowledge。
R3 · 彻底替换 core/llm_client.py
让 OpenAICompatAdapter 直接基于 httpx 实现，而非回退到旧单例；随后删除 core/llm_client.py，LLMPort 成为唯一 LLM seam。
R4 · 将预测与反馈学习抽象为端口
RiskPredictor 与 FeedbackLearner 混合算法、统计、预警写入，建议拆出 ForecastPort / LearningPort，或用独立 service 收口。
R5 · 把 multimodal 下放到 adapters
PDF / 图片 / 网页内容理解不是核心领域逻辑，应改为 DocumentPort + 适配器，避免 core 膨胀。
R6 · 架构健康度检查脚本
在 CI 中增加：webui/screens 中除 read_model 外不得 import core.db；requests / httpx 只能出现在 adapters；core 中不得 import streamlit。
R7 · 端到端集成测试
当前 146 个用例多为单元测试。增加一条“内存 DB 完整 pipeline”集成测试：采集 → 提取 → 评分 → 预警 → 报告，验证 seams 不泄漏真实网络/文件系统。

🎯 下一步建议

按 leverage 排序，建议先执行 R1（拆分 stores）和 R2（消除 causal 页面泄漏）， 这两件事能让 core 的接口宽度从 82 降到约 20，并让 WebUI 层彻底无 direct DB。

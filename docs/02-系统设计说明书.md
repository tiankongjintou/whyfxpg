## 三、数据流向（完整链路）

### 3.1 端到端流水线

```
┌─────────────────────────────────────────────────────────────────────┐
│                        采集阶段（Fetch）                              │
│  monitor_sources → http_source_adapter → raw_pages                   │
│  (定时轮询A类数据源，EU Safety Gate/US CPSC/UK OPSS/AU产品安全)        │
└─────────────────────────────────────────────────────────────────────┘
                                  ↓
┌─────────────────────────────────────────────────────────────────────┐
│                        解析阶段（Extract）                            │
│  raw_pages → extract_engine → risk_events                           │
│  (从HTML中提取产品名/制造商/危害类型/严重度/原始文本/发布时间)           │
│  ⚠️ 待修复：extracted_language（原文语言）字段缺失                     │
└─────────────────────────────────────────────────────────────────────┘
                                  ↓
┌─────────────────────────────────────────────────────────────────────┐
│                        评分阶段（Evaluate）                          │
│  risk_events → risk_scorer → risk_events(total_score/rs_level)       │
│  (六维评分：严重度×概率×国别系数×品类系数×历史系数×证据系数)            │
│  ⚠️ 待修复：时效分（decay）未实现                                     │
└─────────────────────────────────────────────────────────────────────┘
                                  ↓
┌─────────────────────────────────────────────────────────────────────┐
│                        图谱增强（Enrich）                             │
│  risk_events → causal_knowledge → risk_events(causal_factor)         │
│  (因果因子注入，基于制造商节点风险评分)                                 │
└─────────────────────────────────────────────────────────────────────┘
                                  ↓
┌─────────────────────────────────────────────────────────────────────┐
│                        预警阶段（Alert）                              │
│  risk_events + alert_rules → alert_engine → alert_records            │
│  (规则匹配，触发预警动作)                                             │
└─────────────────────────────────────────────────────────────────────┘
                                  ↓
┌─────────────────────────────────────────────────────────────────────┐
│                        复核阶段（Review）                            │
│  manual_reviews → feedback_learner → risk_model系数调整              │
│  (人工修正记录触发模型自我优化)                                        │
└─────────────────────────────────────────────────────────────────────┘
                                  ↓
┌─────────────────────────────────────────────────────────────────────┐
│                        归档阶段（Archive）                           │
│  pipeline_runs → file_system_archive → 压缩包                        │
│  (流水线运行记录归档)                                                 │
└─────────────────────────────────────────────────────────────────────┘
```

## 五、已发现的具体缺陷

### 5.1 多语言字段缺失

**缺陷**：`risk_events` 表缺少 `extracted_language` 字段（需求书中定义的原文语言标注字段）。

- 需求书定义：原始文本描述字段需携带"原文语言"用于判断是否需要多语言处理
- 当前实现：`risk_events` 表有 `original_text` 字段，但无 `extracted_language` 字段
- 影响：多语言风险信号挖掘功能无法区分语种

### 5.2 企业实体未实现

**缺陷**：系统中不存在 `enterprise_entities` 企业实体表。

- 需求书定义：附录B定义了完整的企业实体表结构（enterprise_id/name/enterprise_type/credit_level/risk_profile等）
- 当前实现：仅有 `enterprise_risk_summary` 汇总表，按制造商聚合，无独立企业节点
- 影响：企业关联知识图谱、企业合规画像、关联模式识别等高级功能无法实现

### 5.3 查验记录表未使用

**缺陷**：`inspection_records` 查验记录表在需求书附录D中定义，但代码中无任何使用。

- 需求书定义：查验记录表应关联报关单号、被查验企业、查验结果、违规类型
- 当前实现：数据库中无此表（`❌ 缺失`）
- 影响：D类内部数据源接入能力缺失

### 5.4 自然语言规则配置未实现

**缺陷**：`alert_rules` 表结构中无 `condition_json` 和 `raw_text` 字段。

- 需求书定义：预警规则应支持自然语言原始输入（raw_text）和结构化条件表达式（condition_json）
- 当前实现：`AlertRule` 模型仅有 `condition: Dict` 字段，无独立 `raw_text` 存储
- 影响：业务人员无法以自然语言配置预警规则

### 5.5 时效衰减未实现

**缺陷**：风险评分中无时效维度衰减机制。

- 需求书定义：时效分应基于"发布时间 vs 当前时间 + 衰减曲线"计算
- 当前实现：评分公式为 `ss × ps × country × product × history × evidence × causal`，无时效因子
- 影响：历史事件与新事件在评分上等权，无法体现风险的时间衰减特性

### 5.6 LLM端口无实现

**缺陷**：`ports/llm_port.py` 定义了接口，但无对应适配器实现。

- 影响：多语言语义理解、自然语言规则解析、文档智能解析等AI功能无法启用
